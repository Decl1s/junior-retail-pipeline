# Архитектура и принятые решения

Приложение разделяет чтение данных через Python CSV, преобразования через SQL,
хранение в одном локальном файле DuckDB и выгрузки CSV, Parquet со сжатием Zstandard,
JSON и HTML. Дополнительная библиотека таблиц в памяти не нужна.

1. Прочитать CSV в UTF-8 с ограничением размера и точным заголовком.
2. Вычислить SHA-256 содержимого: имя и путь локального файла не влияют на повторную загрузку.
3. Открыть одну транзакцию для всех новых файлов текущего запуска.
4. Проверить значения через SQL и `try_cast`, ошибочные строки отправить в карантин.
5. Проверить неизменность событий, уникальность версий, стабильные поля заказа
   и неубывание времени обновления между версиями.
6. Добавить уникальные события в bronze, выбрать наибольшую версию заказа для silver.
7. Пересчитать витрины gold и сверить выручку заказов, дней и товаров.
8. Вместе сохранить контроль загрузки файлов, таблицы продаж и журнал запуска.
9. Подготовить полную выгрузку во временной папке и заменить прежнюю отмеченную выгрузку.

В этом проекте bronze хранит **проверенные нормализованные события**.
Исходные CSV остаются локально во входной папке. Карантин содержит хэш источника,
номер строки и код причины; исходные значения и приватные имена файлов туда не копируются.

## Поведение при ошибках

Отдельная некорректная строка исключается из таблиц продаж и учитывается в карантине.
Неверный заголовок, сломанный CSV, конфликт события или несходящиеся суммы отменяют
весь новый пакет. Прежние загрузки сохраняются. Хэши источников записываются
в той же транзакции, что и события: повторный запуск не пропустит неудавшуюся загрузку.

База и файловая система не образуют общую ACID-транзакцию. После успешного коммита
может сломаться выгрузка; сообщение объясняет, что база уже сохранена.
Повторный запуск пропускает загруженные файлы и восстанавливает отчёт.
Временная папка не позволяет смешать файлы старой и новой выгрузки, но замена папок
не гарантирует атомарность при аварии на каждой ОС. Читатель может ненадолго не увидеть
папку результатов. Одновременные процессы записи запускать не следует.

## Ограничения модели

Это учебная пакетная обработка на одном компьютере. Python держит новый пакет в памяти,
витрины пересчитываются целиком. Нет планировщика, распределённого движка, удалённых
источников, dbt, миграций схемы, пересчёта валют и автоматического удаления заказов.
Исправление данных оформляется новой версией; история событий остаётся неизменной.
Для удаления можно позднее добавить отдельный тип события.

Файлы SQL хранятся вместе с исходниками. Новое поле требует изменения контракта
и продуманной миграции. При переводе интерфейса на русский справочник обновляет
названия и категории существующих демотоваров; события и суммы не изменяются.
