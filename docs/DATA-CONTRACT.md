# Схема CSV и правила данных

CSV в кодировке UTF-8 с заголовком в указанном порядке. В заказе одна товарная позиция.
Лишние или отсутствующие поля в отдельной строке отправляют её в карантин.
Другой заголовок отменяет весь пакет. Пробелы по краям значений удаляются.
Идентификаторы демо синтетические и не относятся к людям.

```text
event_id,order_id,version,ordered_at,updated_at,status,product_id,quantity,unit_price_cents,country
```

| Поле | Значение и проверка |
| --- | --- |
| event_id | Неизменный код: латинский префикс в верхнем регистре, 8 цифр и необязательный числовой суффикс; например EVT-00000001-1 |
| order_id | ORD- и ровно 8 цифр |
| version | Целое число от 1 до 1 000 000; побеждает наибольшая версия |
| ordered_at | Корректная дата UTC в формате YYYY-MM-DDTHH:MM:SSZ |
| updated_at | Тот же формат; не раньше заказа, не убывает между версиями |
| status | paid — оплачен, cancelled — отменён, refunded — возвращён |
| product_id | SKU-01…SKU-06; должен существовать в справочнике |
| quantity | Целое число 1…1 000; дробная и научная запись запрещены |
| unit_price_cents | Целое число 1…10 000 000, цена в центах USD |
| country | GB, DE, FR, US или CA; код рынка, без адресов людей |

Нельзя повторно использовать код события с изменённым нормализованным содержимым.
Пара `(order_id, version)` соответствует одному событию. Исходная дата заказа,
товар и страна не меняются; статус, количество и цена могут изменяться в новых версиях.
Конфликт отменяет весь новый пакет. Полностью одинаковые события пропускаются.
Полей для ФИО, почты, адресов, счетов и банковских карт нет.

## Таблицы и детализация

| Таблица | Одна строка соответствует |
| --- | --- |
| bronze.events | Неизменному событию с уникальным event_id и парой заказ/версия |
| silver.products | Демотовару |
| silver.orders | Последней известной версии заказа |
| gold.daily_sales | Исходной дате заказа и стране |
| gold.product_sales | Товару |
| gold.quality_summary | Причине ошибки, накопленной по всем загрузкам |
| audit.sources | Загруженному содержимому CSV с хэшем SHA-256 |
| audit.quarantine | Хэшу источника и позиции строки; хранится первая причина отказа |
| audit.runs | Успешному запуску, включая повторы без новых данных |

Выручка — сумма BIGINT `quantity * unit_price_cents` для заказов с текущим статусом paid.
Суммы возвратов показаны отдельно. Валюта одна, округления и пересчёт валют отсутствуют.
Модель показывает состояние заказов, а не журнал платежей.
Имена полей, коды статусов и файлы выгрузок сохраняют стандартную техническую запись;
человеческие подписи и названия товаров в отчёте — русские.
